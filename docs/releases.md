# 自动发布

沿用智能音箱插件的发布规则：推送到 `main` 后，Release Plugin 工作流按主线顺序逐一构建尚未发布的非文档提交。一批提交或构建期间到达的新提交均逐个出包。仅修改 Markdown（`.md` / `.mdx`）或 `docs/` 下内容的提交不发包、不占序号，后续手动运行也不会补发它们；与代码混合修改时正常出包。工作流生成的版本元数据提交不再发包。

版本为北京时间 `YYYY.M.D.N`，当天首包从 `.0` 开始，后续按已有 tag 的最大序号加一。三段 `D` 与四段 `D.0` 数值相同，迁移同一天已存在三段 tag 时从 `.1` 开始。保留旧 tag 和 Release，已分配的序号不复用；不允许通过输入版本号覆盖已有包。

每个源码提交在隔离 worktree 内执行 `npm ci`、构建、产物清单及哈希校验、类型检查和全部测试，全部通过才推送 tag 和发布 ZIP。`Source commit`、包内 `plugin.json.releaseSource` 和 tag 的父提交记录对应源码；主线元数据提交同步版本、下载地址和包哈希。插件没有独立前端工程，不执行智能音箱插件的 Vue 前端命令。

发布成功但主线元数据推送失败时，续跑接回已发布的同一源码包，不重复发版。质量检查失败时不跳过该源码提交。工作流串行处理，手动运行 Release Plugin 可续跑队列。

本次从旧手动工作流迁移，初始检查点设为迁移前 HEAD `52f75bb20765fcf65e8b594b59bf8001a3f7bfad`：从引入自动发布的首个新提交开始出包，旧历史不补发。首个新包包含该检查点已有的全部代码；检查点仅用于迁移，不表示这个旧 SHA 曾单独发布。首个包完成后，`releaseSource` 由工作流更新为真实发布源码。

本地验证：

```bash
npm ci
npm test
npm run typecheck
npm run build
npm run validate
```

`validate` 读取 `dist/_build/plugin.json`，校验真实入口和静态资源的哈希，不依赖发布前主线清单中尚未写入的哈希。发布流程测试使用本地 bare Git 远端和模拟 GitHub Release，覆盖批量提交、新提交到达、跨日、纯文档跳过、失败续跑、元数据恢复、迁移检查点和 tag/源码一致性，不发布到真实 GitHub。
